# capabilities/ — LRA agent capability system

Canonical home of agent task routing and instructions.
ONE capability = ONE folder = trigger + procedure + bound verifier.

## Layout

- `manifest.yaml`            the only route authority (task -> route packet)
- `ENTRYPOINT.md`            global instruction layer loaded for every task
- `resolve.py`               resolves (repo, task) to a bounded eager packet
- `overlays-config.yaml`     repo registry (kind, title, layout, volume notes)
- `overlays/<repo>.md`       canonical per-repo overlay, eager-loaded for every
                             task; volume overlays are GENERATED by
                             `generate_overlays.py`, all other kinds are
                             hand-maintained
- `<capability>/`            `capability.md` (procedure) + optional bound
                             verifier
- `reference-index.md`       shared lazy reference map
- `generate_task_index.py`   regenerates the human route view
                             (`capabilities/task-index.md`)
- `index.md`                 routing pointer

## Hard invariant

A generate capability is NOT complete until its bound verifier exits 0 on the
written artifact.

## Adding the next capability

1. Copy a small existing capability directory as a structural template.
2. Write `capability.md` (trigger, reads, procedure, bound verifier).
3. Add ONE route to `manifest.yaml`, then run
   `python capabilities/generate_task_index.py` and
   `python tools/governance/audit_governance_context.py`.
4. MOVE any old standard/workflow/prompt content into `capability.md` and
   DELETE the sources. Net file count must drop.

## Migration rule

Port by MOVING text, not rewriting rules. A diff should be mostly moves.

## Entrypoint and vendor wrappers

The root `AGENTS.md` is the repository bootstrap: it locates governance and
runs `resolve.py`. The resolver loads, in order: the manifest's entrypoint,
`overlays/<repo>.md`, then the route's eager instructions — nothing else is
eager. Token budgets cover the wrapper plus that packet and are enforced by
`resolve.py` and audited by `tools/governance/audit_governance_context.py`.

Provider wrappers for downstream repos are generated pointer/bootstrap
artifacts (`tools/governance/generate_agent_wrappers.py` from
`tools/governance/templates/*.j2`). They must not fork the global instruction
layer or embed a second routing table. Edit the canonical sources and
regenerate; do not patch generated downstream wrappers by hand.
